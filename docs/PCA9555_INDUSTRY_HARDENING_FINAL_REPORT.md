## Executive Summary

The hardening branch substantially improves the PCA9555 driver: the core is
framework-neutral, I2C ownership is injected, dirty-state diagnostics exist,
runtime output enabling is latch-preloaded, interrupt/errata behavior is explicit,
native fault tests are broad, and ESP-IDF component/example packaging exists.

The branch is not ready to merge as-is. The local base is stale relative to
`origin/main`, which already contains overlapping IDF-port files. The hardening
branch also contains many untracked files that are required by README/CI and
must be included deliberately. Versioning is unresolved for source-compatibility
significant public API changes, especially deleted copy/move operations.

The branch is not ready to release. Hardware validation is entirely `NOT RUN`,
local pure ESP-IDF builds cannot run because `idf.py` is unavailable, and the
selected release version/release notes are not decided.

## What Changed

- Core portability: Arduino/Wire/platform timing dependencies were removed from
  `include/` and `src/`; transport and timing are injected through `Config`.
- Ownership and lifecycle contracts were clarified: I2C remains application-owned
  and the driver remains managed synchronous.
- Dirty-state diagnostics were added for failed/partial writable-register writes.
- Runtime output enabling was hardened so input-to-output transitions preload
  the output latch before clearing configuration bits.
- Interrupt service APIs and the PCA9555 errata workaround were made explicit,
  including optional lock hooks for compound input-read plus pointer-park
  serialization.
- Native fake transport coverage was expanded across address, register,
  partial-write, short-read/write, health, offline, and errata paths.
- ESP-IDF component metadata, a native IDF diagnostic example, and an IDF example
  contract guard were added.
- Documentation was updated with release gates, a hardware validation matrix,
  corrected register defaults, safety notes, and pre-production wording.

## Public API Changes

- `PCA9555::PCA9555` copy and move constructors/assignments are deleted.
- `SettingsSnapshot` includes `hardwareStateDirty` and
  `hardwareStateDirtyError`.
- New dirty-state accessors:
  - `hardwareStateDirty()`
  - `hardwareStateDirtyError()`
- New or clarified safe direction/output APIs:
  - `preloadOutput(Pin pin, bool high)`
  - `preloadOutputs(uint16_t mask, uint16_t values)`
  - `setDirection(Pin pin, Direction direction)`
  - `configureOutputs(uint16_t outputMask, uint16_t outputValues)`
- New interrupt/errata APIs:
  - `readInputsAndClearInterrupt(uint16_t& value)`
  - `clearInterrupts()`
  - `applyInterruptErrataWorkaround()`
- New optional `Config` lock hooks:
  - `i2cLock`
  - `i2cUnlock`
  - `lockUser`
- `Status::Err::IN_PROGRESS` is documented as a neutral transport pass-through,
  not generated by the driver.

Migration notes exist in README and CHANGELOG. Copy/move deletion is still a
release-versioning issue: keep it only with a major version or explicit
compatibility decision.

## Tests Added

Native Unity coverage now includes 126 tests. Major areas covered:

- address matrix and invalid address rejection,
- default/plausibility checks,
- safe begin/recover ordering,
- dirty-state write failures and partial writes,
- short writes, short reads, unavailable data, and error matrices,
- offline latch and recovery behavior,
- input-read interrupt/errata paths,
- lock acquire/release and interleaving prevention,
- direct register command matrix and pair auto-increment wrap,
- fake input/output/polarity semantics,
- safe output latch preload before configuration writes,
- output-to-input register write behavior,
- copy/move deletion static coverage.
